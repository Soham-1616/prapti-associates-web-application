# DEPLOYMENT GUIDE — PRAPTI ASSOCIATES

This document details the complete instructions for deploying the Prapti Associates website and CMS dashboard from scratch.

---

## 1. Prerequisites

### System Requirements
- **Node.js:** version `18.x` or `20.x` (LTS recommended)
- **npm:** version `9.x` or higher

---

## 2. Server Startup Sequence

### Step 1: Install Node.js
Ensure Node.js is installed. Verify the installation:
```bash
node -v
npm -v
```

### Step 2: Extract / Clone Repository
Navigate to the directory:
```bash
cd "Prapti Associates"
```

### Step 3: Install Package Dependencies
Navigate to the `backend` folder and install dependencies:
```bash
cd backend
npm install
```

### Step 4: Create Environment Configuration
In the `backend/` folder, create a file named `.env`. Use the following template:
```env
PORT=5000
JWT_SECRET=<YOUR_LONG_RANDOM_SECRET_KEY>
EMAIL_USER=<YOUR_GMAIL_ADDRESS>
EMAIL_PASS=<YOUR_GMAIL_APP_PASSWORD>
ADMIN_EMAIL=<ADMIN_NOTIFICATION_RECEIVER_EMAIL>
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH=$2b$10$RwsnNe9WgW7aW98PI5Zyiux9YJENpoqu/.S3Pynqi7wkLG2dJAHgK
BASE_URL=http://localhost:5000
```
*Note: To generate a secure `ADMIN_PASSWORD_HASH`, hash your desired plaintext password using Bcrypt with a cost factor of 10.*

### Step 5: Start the API Backend Server
Run the startup script in the `backend` folder:
```bash
# For Development (runs nodemon, auto-reloading changes)
npm run dev

# For Production
npm start
```
Verify the server starts with:
`🏗️ Prapti Associates API Server Running on: http://localhost:5000`

### Step 6: Start the Frontend Static Server
Open a new terminal window at the project root directory and serve frontend files:
```bash
npx serve -p 5500 --no-clipboard
```
Verify the output:
`INFO Accepting connections at http://localhost:5500`

## 3. Production Deployment (PaaS Guide — e.g., Render)

To make the platform public, deploy the backend application to a platform like Render or Heroku, and host the static frontend on Vercel, Netlify, or Github Pages.

### Backend Deployment (Render)
1. **GitHub Preparation:** Push the codebase to a private/public GitHub repository.
2. **Create Web Service:** Create a new Web Service on Render and link your repository.
3. **Configurations:**
   - **Root Directory:** `backend`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. **Environment Variables:** Define the following variables under the **Environment** settings page on Render:
   - `PORT`: `5000`
   - `JWT_SECRET`
   - `EMAIL_USER`
   - `EMAIL_PASS` (Must be a 16-character Google App Password)
   - `ADMIN_EMAIL`
   - `BASE_URL` (Set this to the public URL generated by Render, e.g., `https://prapti-backend.onrender.com`)
5. **Persistent Storage (Recommended):** Since Render resets the local container file system on restarts, mount a persistent disk to avoid losing uploaded files and dynamic data:
   - **Mount Path:** `/opt/render/project/src/backend/data` (Or migrate state updates to a database if needed).

### Frontend Deployment (Netlify/Vercel)
1. **API URL Alignment:** In the frontend JavaScript files under `js/`, change references to `http://localhost:5000` to your live backend domain:
   - File: `js/forms.js` (`var API_BASE_URL`)
   - File: `js/about.js` (`var ABOUT_API`)
   - File: `js/connections.js` (`var CONNECTIONS_API`)
   - File: `js/contact-page.js` (`var CONTACT_API`)
   - File: `js/homepage.js` (`var HOMEPAGE_API`)
   - File: `js/projects.js` (`var PROJECTS_API`)
   - File: `js/services.js` (`var SERVICES_API`)
   - File: `js/admin.js` (`var ADMIN_API`)
2. **Build Configurations:**
   - **Build Command:** (Leave blank / static files)
   - **Output Directory:** `.` (root directory)
3. **URL Rewriting:** Ensure `serve.json` is supported, or configure redirects (e.g., `_redirects` for Netlify) to map cleaner URL paths.

## 4. Troubleshooting

### Port Conflicts
- **Error:** `EADDRINUSE: address already in use :::5000`
- **Solution:** Another program is using port 5000. Open `backend/.env` and change `PORT=5000` to `PORT=5001`. Update references accordingly.

### Email Delivery Failures
- **Error:** `Authentication credentials invalid` / `SMTP connection timeout`
- **Solution:** Gmail rejects direct login attempts using standard passwords. You MUST enable 2-Step Verification on the Gmail account and generate a 16-character **App Password** for `EMAIL_PASS`.

### Image Upload Failures
- **Error:** `400 Bad Request` / `Only JPG, JPEG, PNG, and WEBP images are allowed`
- **Solution:** Ensure the file size is under 5MB per upload. Validate that the file extension is strictly lowercase.

### Changes Not Reflecting on the Public Site
- **Error:** Public pages display hardcoded text instead of backend updates.
- **Solution:** Check the browser console. If `Blocked by CORS` errors are logged, ensure the backend middleware has CORS enabled for the domain.
