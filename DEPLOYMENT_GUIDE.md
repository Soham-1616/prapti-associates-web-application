# DEPLOYMENT GUIDE — PRAPTI ASSOCIATES

This document details the complete instructions for deploying the Prapti Associates website and CMS dashboard from scratch.

---

## 1. Prerequisites

### System Requirements
- **Node.js:** version `18.x` or `20.x` (LTS recommended)
- **npm:** version `9.x` or higher

---

## 2. Server Startup Sequence

### Step 1: Install Node.js
Ensure Node.js is installed. Verify the installation:
```bash
node -v
npm -v
```

### Step 2: Extract / Clone Repository
Navigate to the directory:
```bash
cd "Prapti Associates"
```

### Step 3: Install Package Dependencies
Navigate to the `backend` folder and install dependencies:
```bash
cd backend
npm install
```

### Step 4: Create Environment Configuration
In the `backend/` folder, create a file named `.env`. Use the following template:
```env
PORT=5000
JWT_SECRET=<YOUR_LONG_RANDOM_SECRET_KEY>
BREVO_API_KEY=<YOUR_BREVO_API_KEY>
SENDER_EMAIL=<YOUR_SENDER_EMAIL>
ADMIN_EMAIL=<ADMIN_NOTIFICATION_RECEIVER_EMAIL>
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH=<YOUR_BCRYPT_PASSWORD_HASH>
BASE_URL=http://localhost:5000
```

**To generate `ADMIN_PASSWORD_HASH`:**
```bash
node -e "require('bcryptjs').hash('YOUR_PASSWORD', 10).then(h => console.log(h))"
```

### Step 5: Generate Admin Credentials
After setting up `.env`, generate the initial `admin.json`:
```bash
node -e "
const bcrypt = require('bcryptjs');
const fs = require('fs');
bcrypt.hash('YOUR_PASSWORD', 10).then(hash => {
  fs.writeFileSync('data/admin.json', JSON.stringify({ username: 'admin', passwordHash: hash }, null, 4));
  console.log('Admin credentials saved to data/admin.json');
});
"
```

### Step 6: Start the API Backend Server
Run the startup script in the `backend` folder:
```bash
# For Development (auto-reloading)
npm run dev

# For Production
npm start
```
Verify the server starts with:
`🏗️ Prapti Associates API Server Running on: http://localhost:5000`

### Step 7: Start the Frontend Static Server
Open a new terminal window at the project root directory and serve frontend files:
```bash
npx serve -p 5500 --no-clipboard
```
Verify the output:
`INFO Accepting connections at http://localhost:5500`

## 3. Production Deployment (PaaS Guide — e.g., Render)

### Backend Deployment (Render)
1. **GitHub Preparation:** Push the codebase to a GitHub repository.
2. **Create Web Service:** Create a new Web Service on Render and link your repository.
3. **Configurations:**
   - **Root Directory:** `backend`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. **Environment Variables:** Define the following variables under Render's **Environment** settings:
   - `PORT`: `5000`
   - `JWT_SECRET`
   - `BREVO_API_KEY`
   - `SENDER_EMAIL`
   - `ADMIN_EMAIL`
   - `ADMIN_USERNAME`
   - `ADMIN_PASSWORD_HASH`
   - `BASE_URL` (Set this to the public URL generated by Render, e.g., `https://your-app.onrender.com`)
5. **Persistent Storage (Recommended):** Mount a persistent disk to avoid losing uploads on restarts:
   - **Mount Path:** `/opt/render/project/src/backend/data`

### Frontend Deployment (Vercel/Netlify)
1. **API URL Alignment:** In the frontend `js/` files, change `http://localhost:5000` to your live backend domain:
   - `js/admin.js` → `const ADMIN_API`
   - `js/about.js` → `var ABOUT_API`
   - `js/connections.js` → `const API_BASE`
   - `js/contact-page.js` → `var CONTACT_API`
   - `js/forms.js` → `const API_BASE` (2 places)
   - `js/homepage.js` → `var HOMEPAGE_API` + `var SERVICES_API`
   - `js/main.js` → `fetch(...)` (line ~165)
   - `js/projects.js` → `const PROJECTS_API`
   - `js/services.js` → `var SERVICES_API`
   - `project-detail.html` → `const DETAIL_API`
2. **Build Configurations:**
   - **Build Command:** (Leave blank — static files)
   - **Output Directory:** `.` (root directory)
3. **URL Rewriting:** Ensure `serve.json` is supported, or configure redirects for cleaner URL paths.

## 4. Troubleshooting

### Port Conflicts
- **Error:** `EADDRINUSE: address already in use :::5000`
- **Solution:** Change `PORT=5000` to `PORT=5001` in `backend/.env`.

### Email Delivery Failures
- **Error:** `Authentication credentials invalid` / `SMTP connection timeout`
- **Solution:** Verify your Brevo API key is correct. Check that `SENDER_EMAIL` is verified in Brevo.

### Image Upload Failures
- **Error:** `400 Bad Request` / `Only JPG, JPEG, PNG, and WEBP images are allowed`
- **Solution:** Ensure the file size is under 5MB. Validate file extension is `.jpg`, `.jpeg`, `.png`, or `.webp`.

### Changes Not Reflecting on the Public Site
- **Error:** Public pages display hardcoded text instead of backend updates.
- **Solution:** Check the browser console. If `Blocked by CORS` errors appear, ensure the backend has CORS enabled for your frontend domain.
